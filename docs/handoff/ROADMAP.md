# Roadmap

Roadmap организован так, чтобы сначала доказать работоспособность минимального
переключения и только затем увеличивать архитектуру.

## P0 — доказать MVP

Блокирует `v0.1.0`:

1. ⬜ запустить CI в реальном GitHub-репозитории;
2. ✅ зафиксировать `Cargo.lock`;
3. ✅ проверить VID/PID/interface на целевом G6;
4. ✅ аппаратно проверить оба output packet;
5. ⬜ проверить udev-rule на Bluefin (на тестовой машине `/dev/hidraw*` уже
   имели права `0666`, поэтому необходимость правила не изолирована);
6. ⬜ проверить GNOME extension в живой сессии GNOME 50.3;
7. ✅ проверить release install и uninstall;
8. ✅ обновить документацию реальными версиями и результатами.

## P1 — укрепить минимальный переключатель

Часть P1 выполнена досрочно: разведка протокола показала, что read-запрос и ACK
доступны тривиально, поэтому их внесли в `v0.1.0`.

- ✅ реализовать чтение фактического выхода (`0x2c` query);
- ✅ читать и валидировать ACK после записи;
- ✅ добавить timeout (1 с на ответ, фильтрация чужих кадров);
- ✅ расширить `doctor` диагностикой всех matching interfaces;
- ✅ добавить корректное состояние disconnected;
- ✅ добавить `Cargo.lock` в CI;
- ✅ зафиксировать реально поддерживаемые GNOME-версии (48–50);
- ⬜ отделить HID transport от protocol для mock/integration tests;
- ⬜ ограниченные retry при отсутствии ответа;
- ⬜ shellcheck и link checks в CI;
- ⬜ проверить повторную и частично неудачную установку;
- ⬜ атомарная запись state-файла.

Результат P1 — надёжный `v0.2.x`, всё ещё только для двух выходов.

## P2 — улучшить UX без глубокой настройки

- hot-plug detection — устройство уже присылает event-кадры (`5a 6e ...`) при
  смене выхода, слушателя пока нет; это самый дешёвый следующий шаг;
- Quick Settings tile вместо или вместе с panel indicator;
- опциональный one-click toggle;
- локализация;
- сочетание клавиш через GNOME settings;
- более удобный uninstall/upgrade path.

Демон допустим только если hot-plug и двустороннее состояние действительно
требуют постоянного процесса.

## P3 — расширение проекта после стабильного output switch

Отдельная следующая фаза, не часть текущего MVP:

- Rust library `g6-core`;
- user service `g6d` и D-Bus API;
- GTK4/libadwaita settings application;
- профили для headphones/speakers;
- SBX, Scout Mode, EQ и другие reverse-engineered параметры;
- импорт/экспорт профилей;
- поддержка дополнительных моделей только после отдельного исследования.

Каждая аппаратная функция должна иметь собственную protocol documentation,
packet tests, hardware test record и безопасный fallback.

## Не планируется

Даже в долгосрочном направлении по умолчанию не входят:

- firmware flashing/updating;
- обход permission model через root daemon;
- универсальный драйвер всех Creative устройств;
- Windows/macOS клиент;
- облачные аккаунты и синхронизация;
- телеметрия;
- замена PipeWire или полноценный audio server;
- копирование официального Creative UI один в один.

## Правило управления scope

До выпуска `v0.1.0` нельзя принимать feature work по SBX/EQ/профилям в
основную ветку. Допускаются только исправления, тесты, документация, упаковка и
изменения, необходимые для надёжного переключения двух выходов.
