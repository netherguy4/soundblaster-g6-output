## P0 — блокирующие проверки

### 1. CI без устройства

В корне репозитория:

```bash
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-targets --all-features
cargo build --locked --release
bash -n install.sh uninstall.sh scripts/package.sh
python3 -m json.tool extension/metadata.json >/dev/null
node --check extension/extension.js
VERSION=0.1.0-test ./scripts/package.sh
(cd dist && sha256sum -c SHA256SUMS)
```

Ожидается:

- все команды завершаются с кодом `0`;
- unit-тесты подтверждают оба write-пакета и query-пакет;
- `dist/` содержит tarball, extension zip и checksum;
- `Cargo.lock` зафиксирован в репозитории.

**Результат:** ✅ пройдено локально (9 тестов). Сборка не требует libudev.
`node --check` заменялся парсингом через gjs 1.88.1 — Node.js на тестовой
машине отсутствует; в CI выполняется штатный `node --check`.

### 2. Обнаружение G6 на Bluefin

Подключить G6 напрямую к USB и выполнить:

```bash
lsusb | grep -i '041e:3256'
./target/release/g6-output doctor
```

До установки udev-rule допустима ошибка доступа. После `./install.sh`, reconnect
устройства и нового `g6-output doctor` ожидаются:

```text
result:    found
access:    OK
```

**Результат:** ✅ `result: found`, `access: OK`, `device:` печатает фактический
выход.

Зафиксировано:

- `/dev/hidraw7` (interface `4`); interface `3` — это `/dev/hidraw6`;
- `hidapi` с бэкендом `linux-native-basic-udev` видит interface `4` корректно;
- firmware получить не удалось — способ запроса не найден;
- Bluefin 44, GNOME Shell 50.3, kernel 7.0.12.

### 3. Аппаратное переключение CLI

Сначала уменьшить громкость и убедиться, что и наушники, и динамики подключены
безопасно.

```bash
g6-output set headphones
g6-output set speakers
g6-output headphones
g6-output speakers
```

Для каждой команды физически подтвердить, что звук выходит из нужного разъёма.
Повторить не менее пяти циклов.

**Результат:** ✅ соответствие подтверждено на слух (`0x04` — наушники,
`0x02` — динамики), 5 циклов × 2 переключения = 10/10 подтверждены чтением
состояния устройства сразу после каждой команды.

Проверить состояние:

```bash
g6-output status                     # читает устройство
g6-output doctor                     # показывает device и cached рядом
cat "${XDG_STATE_HOME:-$HOME/.local/state}/g6-output/output"
```

Отдельно проверить, что внешнее изменение подхватывается: переключить выход
в обход CLI и убедиться, что `status` показывает новое значение.

**Результат:** ✅ `status` возвращает фактический выход, кеш остаётся
устаревшим и не используется, пока устройство доступно.

### 4. GNOME extension

```bash
gnome-extensions enable soundblaster-g6-output@netherg.io
gnome-extensions info soundblaster-g6-output@netherg.io
```

Проверить:

- индикатор появился после login/reload session;
- оба пункта переключают реальный выход;
- пункты блокируются во время subprocess;
- иконка и подпись обновляются после успеха;
- при отключённом G6 появляется понятная ошибка;
- повторное `disable/enable` не создаёт два индикатора;
- logout/login сохраняет отображение последнего кешированного выбора.

### 5. End-to-end установка из release

На чистом пользовательском профиле или тестовой машине:

```bash
tar -xzf soundblaster-g6-output-0.1.0-test-x86_64.tar.gz
cd soundblaster-g6-output-0.1.0-test-x86_64
./install.sh
g6-output doctor
```

После проверки выполнить:

```bash
./uninstall.sh
```

Убедиться, что отсутствуют:

```text
~/.local/bin/g6-output
~/.local/share/gnome-shell/extensions/soundblaster-g6-output@netherg.io/
${XDG_STATE_HOME:-~/.local/state}/g6-output/
/etc/udev/rules.d/70-soundblaster-g6-output.rules
```

## P1 — негативные и устойчивостные проверки

### Устройство отключено

Все команды `set` должны завершаться ненулевым кодом, не менять кеш и не
показывать ложный успех в GNOME.

### Нет udev-rule или доступа

Удалить/временно переименовать rule, переподключить G6 и проверить понятное
сообщение с рекомендацией проверить правило и reconnect.

### Повреждённый кеш

Записать в state file неизвестное значение.

**Результат:** ✅ мусор в кеше не влияет ни на `status`, ни на `set` —
устройство авторитетнее. `unknown` возвращается только когда устройство есть,
но ответ получить не удалось, и кеш пуст. Вопрос закрыт.

### Отсутствует CLI

Временно убрать `~/.local/bin/g6-output`. Extension должен показать ошибку и не
сломать GNOME Shell.

### Быстрые клики

Несколько раз быстро выбрать пункты меню. `_busy` должен предотвращать
параллельные subprocess внутри одного indicator instance.

### Reconnect и sleep/resume

Проверить команды после:

- unplug/replug;
- USB hub, если он используется постоянно;
- suspend/resume;
- перезапуска пользовательской сессии.

## Матрица совместимости GNOME

Не оставлять версию в `metadata.json` только на основании синтаксиса. Для каждой
заявленной версии хранить результат:

| GNOME | Дистрибутив | Extension загружается | Переключение | Ошибки UI | Проверено кем/когда |
|---:|---|---|---|---|---|
| 48 | — | ⬜ | ⬜ | ⬜ | заявлена по совместимости API |
| 49 | — | ⬜ | ⬜ | ⬜ | заявлена по совместимости API |
| 50 | Bluefin 44 | ⬜ | ⬜ | ⬜ | ожидает установки в живой сессии |

`metadata.json` сужен до 48–50. Версии 45–47 убраны: расширение никогда на них
не проверялось.

Отдельно проверить отмену: выключить extension во время выполняющейся команды
и убедиться, что в журнале нет `Object St.Label ... has been already
deallocated`.

## Как документировать результаты

После теста обновить [STATUS.md](STATUS.md):

- перенести подтверждённые пункты из «требует тестирования»;
- указать точные версии ОС, GNOME, kernel и firmware;
- приложить команды и полный текст ошибок для проваленных проверок;
- не использовать формулировку «работает на Linux вообще» после теста одной
  конфигурации.
