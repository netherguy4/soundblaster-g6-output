# Состояние проекта

Дата первоначального handoff: **26 июля 2026 года**.
Дата аппаратной верификации: **29 июля 2026 года**.

Термины статуса:

- **реализовано** — код существует и логически завершает заявленный сценарий;
- **проверено** — подтверждено запуском на реальном оборудовании или в CI;

```text

Kernel:       7.0.12-201.fc44.x86_64
GNOME Shell:  50.3
gjs:          1.88.1

Firmware:     не опрашивалась (способ получения не найден)
```

## Что проверено на реальном устройстве

- **Обнаружение.** VID `041e`, PID `3256`, interface `4` совпадают с кодом.
  Устройство экспонирует два HID-интерфейса: `3` (Consumer Control) и
  `4` (Vendor-Defined, control) — приложение использует `4`.
- **Транспорт.** Report descriptor interface `4` не содержит Report ID, поэтому
  запись 65 байтами с ведущим `0x00` корректна. См. [ARCHITECTURE.md](ARCHITECTURE.md).
- **Протокол переключения.** Кадр `5a 2c 05 00 <mode>` действительно меняет
  физический выход. Соответствие подтверждено на слух: `0x04` — наушники,
  `0x02` — динамики.
- **Чтение состояния.** Запрос `5a 2c 05 01 00` возвращает фактический текущий
  выход. Это снимает главное ограничение прежнего MVP.
- **Подтверждение записи.** Устройство отвечает на запись кадром с реально
  применённым режимом, что даёт настоящую верификацию вместо доверия к
  системному вызову.
- **Устойчивость.** 5 циклов × 2 переключения = 10 из 10 подтверждены чтением
  состояния сразу после команды. Неконсистентных состояний не возникало.
- **Рассинхрон.** После смены выхода в обход CLI (прямая запись в hidraw)
  `status` показывает новое значение, а не устаревший кеш.
- **Повреждённый кеш.** Мусор в state-файле не влияет ни на `status`, ни на
  `set` — устройство авторитетнее. Открытый вопрос из TESTING.md закрыт.

## Что реализовано

### Rust CLI

- поиск устройства по VID `041e`, PID `3256`, interface `4`;
- команды `set <output>`, `headphones`, `speakers`, `toggle`, `status`,
  `doctor`, `--version`, `--help`;
- чтение фактического выхода из устройства;
- проверка ACK после записи с фильтрацией асинхронных event-кадров по байту
  команды и общим лимитом 1 с;
- строгая проверка длины записи (ровно 65 байт);
- категории ошибок: устройство не найдено, нет доступа, ошибка записи, ошибка
  чтения, нет ответа, неизвестный режим, режим не применён, ошибка локального
  состояния, неправильная команда;
- `doctor` перечисляет альтернативные интерфейсы, если `4` не найден;
- 9 unit-тестов: алиасы, регистр, отказ на неизвестных именах, оба write-пакета,
  query-пакет, round-trip режимов, отказ на неизвестных режимах, `opposite`;
- локальный кеш в `${XDG_STATE_HOME:-~/.local/state}/g6-output/output` как
  резерв для отсоединённого устройства.

### GNOME Shell extension

- индикатор в верхней панели: левый клик переключает выход, правый открывает
  меню с пунктами `Headphones` и `Speakers`;
- состояние показывает иконка, без дублирующей текстовой строки;
- hot-plug через `GUdev`: индикатор скрывается при отключении устройства
  примерно за 0,3 с и возвращается при подключении;
- асинхронный запуск CLI через `Gio.Subprocess` с `Gio.Cancellable`,
  отменяемым в `destroy()`;
- обновление состояния при каждом открытии меню, а не только при старте;
- поиск бинарника в `~/.local/bin`, затем в `PATH`; при отсутствии — понятная
  ошибка вместо молчания;
- защита от параллельных операций через флаг `_busy`;
- notification только при ошибке: успех виден по иконке;
- заявленные версии GNOME Shell 48–50, проверена 50.3.

### Установка и удаление

- установка бинарника в `~/.local/bin` (через временное имя, без `ETXTBSY`);
- установка расширения в пользовательский каталог GNOME;
- udev-rule ставится **первой**, чтобы отказ от sudo не оставлял частичную
  установку;
- предупреждение, если `~/.local/bin` не в `PATH`;
- `TAG+="uaccess"`, а не глобальный `MODE="0666"`;
- полное удаление CLI, extension, локального кеша и udev-rule.

### CI и release

- `cargo fmt --check`, `cargo clippy --locked -D warnings`,
  `cargo test --locked`, `cargo build --locked --release`;
- `Cargo.lock` зафиксирован в репозитории;
- кеширование Cargo, `concurrency` group;
- `bash -n`, JSON-проверка, `node --check` для GJS;
- сверка `VERSION` с версией в `Cargo.toml`;
- `ARCH` определяется через `uname -m`;
- проверка `SHA256SUMS` и в build-, и в release-job;
- публикация GitHub Release для тегов `v*`.

## Что требует тестирования

### Другие конфигурации

- GNOME Shell 48 и 49 (заявлены по совместимости API, не проверялись);
- другие версии firmware G6;
- архитектуры кроме x86_64;
- дистрибутивы кроме Bluefin 44.

### Сценарии, не воспроизведённые локально

- поведение после suspend/resume;
- работа через USB-хаб;
- установка на чистом профиле, где udev-rule реально требуется. Правило
  установлено и действует (у узла появились тег `uaccess` и ACL
  `user:<пользователь>:rw-`), но на тестовой машине `/dev/hidraw*` и без него
  имели права `0666` по другой причине, поэтому его необходимость не была
  доказана изолированно;
- обработка кликов на GNOME 48 и 49: там нет `Clutter.ClickGesture`, работает
  ветка через `vfunc_event`, и она не проверялась.

## Что требует доработки

Не блокирует релиз, но желательно дальше:

- отделить HID transport от protocol для mock/integration tests;
- слушать event-кадры самого устройства (`5a 6e ...`), чтобы подхватывать смену
  выхода сторонней программой без открытия меню;
- локализовать UI или унифицировать весь интерфейс на одном языке;
- добавить shellcheck и markdown/link validation в CI;
- зафиксировать minimum supported Rust version;
- атомарная запись state-файла (сейчас обычный `fs::write`);
- расширить матрицу GNOME реальными результатами.

## Что сейчас не готово

- реакция на смену выхода сторонней программой без действия пользователя:
  состояние обновляется при hot-plug, при открытии меню и при вызове команды,
  но не по событию самого устройства;
- daemon/D-Bus API;
- Quick Settings tile вместо обычного panel indicator;
- GUI настроек;
- упаковка Flatpak, RPM, DEB или Homebrew;
- публикация в GNOME Extensions;
- поддержка нескольких устройств;
- поддержка других Sound Blaster моделей;
- SBX, Scout Mode, EQ, Direct Mode, gain, mixer и firmware-функции.

## Что не планируется в рамках этого MVP

- глубокая настройка G6;
- замена PipeWire/PulseAudio или управление их routing;
- root-демон для постоянного доступа к устройству;
- интерфейс GNOME целиком на Rust: GNOME Shell extension остаётся на GJS;
- Windows или macOS версия;
- поддержка произвольных Creative USB-устройств;
- телеметрия, аналитика, аккаунты и облачная синхронизация;
- автоматическое обновление firmware;
- обход системной модели доступа к USB через `sudo` при каждом переключении.
