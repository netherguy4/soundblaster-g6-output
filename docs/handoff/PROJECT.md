# Проект и его назначение

## Проблема

Sound BlasterX G6 умеет выводить звук через разъём наушников или линейный выход
для динамиков. В Linux нет официального приложения Creative с удобным
переключателем этих физических выходов. Обычный выбор устройства в GNOME или
PipeWire не решает задачу полностью: требуется отправить управляющую HID-команду
самому G6.

Пользователю приходится использовать Windows, сторонние экспериментальные
утилиты или вручную запускать низкоуровневые команды. Это неудобно для частого
переключения на рабочем Linux-десктопе.

## Назначение

Проект предоставляет минимальный, понятный и удаляемый без остатка способ:

1. выбрать `Headphones` или `Speakers` из верхней панели GNOME;
2. выполнить то же действие из терминала;
3. установить всё одним скриптом;
4. удалить всё одним скриптом;
5. собирать готовые release-архивы через GitHub Actions.

## Целевой пользователь

Основной сценарий — один пользователь GNOME/Bluefin с одним Sound BlasterX G6,
который регулярно переключается между наушниками и динамиками и не хочет
запускать Windows или полноразмерное приложение.

Проект пока не рассчитан на системное многопользовательское развёртывание,
несколько одновременно подключённых G6 или другие модели Sound Blaster.

## Решение

- `g6-output` на Rust находит HID-интерфейс G6 и отправляет команду выбора выхода.
- GNOME Shell extension на GJS показывает индикатор и асинхронно вызывает CLI.
- udev-rule выдаёт активному локальному пользователю доступ к `hidraw` через
  `TAG+="uaccess"`.
- локальный файл состояния хранит последний выход, успешно выбранный этим CLI.
- install/uninstall scripts управляют пользовательскими файлами и udev-rule.
- GitHub Actions проверяет исходники, собирает бинарник и создаёт release-пакеты.

## Границы MVP

В MVP входит только:

- обнаружение G6 по фиксированным VID/PID/interface;
- установка выхода `headphones` или `speakers`;
- CLI-команды `set`, `toggle`, `status`, `doctor`;
- простой индикатор GNOME;
- локальный кеш последнего выбора;
- установка, удаление и CI/release workflow.

## Критерии успеха MVP

MVP можно считать успешным, когда на целевой Bluefin-системе подтверждено, что:

- пользователь без root переключает оба физических выхода;
- переключение из GNOME не подвешивает Shell;
- понятная ошибка показывается при отключённом устройстве или отсутствии прав;
- установка из release-архива работает по README;
- удаление убирает CLI, расширение, состояние и udev-rule;
- GitHub Actions проходит на push/PR и публикует артефакты по тегу.

Полный список проверок находится в [TESTING.md](TESTING.md).

## Ограничения и допущения

- USB HID-протокол не является официально документированным Creative API.
- Команда основана на публичном reverse-engineering сообщества.
- Интерфейс `4` и значения режимов должны быть проверены на конкретной ревизии и
  прошивке устройства.
- GNOME extension API меняется между выпусками; декларация поддержки версии в
  `metadata.json` сама по себе не доказывает совместимость.
- Кеш не замечает переключения, выполненные в Windows или другой утилите.
